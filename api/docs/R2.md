# Cloudflare R2 — configuração e teste

Bucket utilizado: `psa-gestor-arquivos`. O bucket permanece privado e os downloads passam pela API, após autorização. Credenciais S3 ficam somente no backend.

## Executar com MariaDB e R2 real

Execute `.\scripts\Iniciar-ApiLocal.ps1` conforme [MariaDB local](MARIADB_LOCAL.md). A API usa os perfis `local,demonstracao,r2,r2-local` e acessa o MariaDB por `127.0.0.1:3306`. As credenciais R2 permanecem no arquivo privado `config/application-r2-local.yml` carregado pelo Spring Boot; não integram o JAR nem a imagem.

## Credenciais

O cliente S3 utiliza `Access Key ID` e `Secret Access Key`. O valor separado do token Cloudflare não é necessário e não é armazenado pelo projeto. As permissões devem ser de leitura e gravação de objetos, limitadas ao bucket do projeto.

Para substituir as credenciais, edite somente o arquivo privado `config/application-r2-local.yml` e reinicie a API. Não coloque segredos no arquivo de exemplo, no Angular ou nos documentos compartilhados. Credenciais expostas devem ser revogadas e substituídas no painel Cloudflare.

Na futura VPS, use variáveis de ambiente ou secrets: `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY` e `R2_SECRET_KEY`, com o perfil `prod`. Não envie o arquivo local de credenciais para o repositório.

## Teste automatizado no bucket real

O teste externo fica desativado por padrão para que `mvnw test` não acesse a Cloudflare. Para executá-lo explicitamente:

```powershell
$env:JAVA_HOME = 'C:/Program Files/Java/jdk-25.0.4.1'
$env:PSA_R2_LIVE_TEST = 'true'
try {
    .\mvnw.cmd '-Dtest=R2LiveTest' test
} finally {
    Remove-Item Env:PSA_R2_LIVE_TEST -ErrorAction SilentlyContinue
}
```

O teste usa uma chave aleatória em `testes-integracao/`, envia conteúdo fictício, compara os bytes baixados, verifica tamanho e tipo, exclui somente o objeto criado e confirma HTTP 404 ao consultar seus metadados. Não lista nem altera arquivos preexistentes e não se conecta ao banco.

**Resultado de 16/10/2026:** teste real concluído com sucesso no bucket `psa-gestor-arquivos`, incluindo confirmação da exclusão. Os testes de seleção de perfis também confirmaram que há um único adaptador ativo nos cenários de armazenamento local de testes e remoto.

Esse resultado valida as credenciais, as permissões e as operações S3 do adaptador a partir do ambiente de desenvolvimento. Upload/download autenticado pela API já tem cobertura local; o fluxo completo pela VPS/Angular ainda requer homologação nesse ambiente.
